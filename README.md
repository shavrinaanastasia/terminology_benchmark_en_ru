# Terminology Benchmark EN→RU

Бенчмарк, который проверяет, насколько правильно машинный перевод передаёт **научные термины** с английского на русский.

Берём свежие аннотации статей с arXiv, переводим их целиком системой машинного перевода и оцениваем только термины. Используются три способа проверки, от строгого строкового до LLM-судьи.

## Данные

- **10 статей arXiv**, опубликованных не раньше чем за 2 недели до сбора (6–12 ноября 2026 г.). Поэтому их текстов, скорее всего, ещё нет в обучающих данных переводчиков.
- **10 разных областей**, по одной статье на категорию: квантовая физика, ИИ, гидродинамика, теория информации, робототехника, оптика, астрофизика, статистика/генетика, дискретная математика, компьютерная графика.
- Текст статьи — это заголовок плюс аннотация, 120–300 слов.
- **67 терминов**, по 6–7 на статью. Для каждого термина есть эталонный русский перевод и список допустимых вариантов: синонимы, аббревиатуры, другие устоявшиеся формы.

## Метрики

Переводится весь текст статьи, а оцениваются только размеченные термины. Балл статьи — доля правильно переведённых терминов. Итог по бенчмарку — среднее по статьям.

### 1. Точная подстрока

Эталон или один из допустимых вариантов ищется в переводе как подстрока. Перед сравнением оба текста нормализуются: нижний регистр, `ё → е`, единые дефисы, без кавычек.

Метод слишком строгий для русского языка. «гильбертово пространство» не находится в тексте «…в гильбертовом пространстве», хотя перевод верный.

### 2. Подстрока по основам слов

Каждое слово эталона длиннее 4 букв обрезается на 3 буквы с конца (основа не короче 4 букв). Затем термин ищется регулярным выражением с любыми окончаниями, например `гильберт\w*[\s-]+пространс`.

Метод засчитывает падежные и числовые формы, но ловит неверный выбор слова: «правила **супервыбора**» не совпадает с основой эталона «правило **суперотб**ора». Ограничение: правильный синоним, которого нет в списке вариантов, будет засчитан как ошибка.

### 3. LLM-судья (Gemini 3.8 Flash)

Судья получает английский исходник, перевод и список английских терминов. Эталонных переводов он **не видит**. Для каждого термина судья:

1. выписывает, как термин передан в переводе;
2. пишет обоснование, 1–3 предложения;
3. ставит оценку:
   - `1` — так термин называют в русскоязычной научной литературе этой области;
   - `0` — термин пропущен, переведён калькой, искажён по смыслу, переведён непоследовательно или грамматически сломан.

Ответ возвращается строго в JSON, температура 0. Промпт лежит в `nirvana_code/judge_prep_full.py`.

### Типичные ошибки переводчика (по оценке судьи)

| Термин | В переводе | Эталон |
|---|---|---|
| superselection rule | правила супервыбора | правило суперотбора |
| prompt injection | быстрого внедрения | промпт-инъекция |
| maximum spanning tree | максимальным охватом дерева | максимальное остовное дерево |
| pangenome graph | графика пангенома | пангеномный граф |
| fluorescence lifetime | срок службы флуоресценции | время жизни флуоресценции |
| path tracing | трассировки траектории | трассировка путей |
| vision language navigation | Навигация на языке Vision language | навигация на основе зрения и языка |

### Что показывает сравнение метрик

- Точная подстрока в основном штрафует за склонение, а не за ошибки. Как самостоятельная метрика она неинформативна.
- Метрика по основам и судья дают близкие средние (66% и 64%), но расходятся на отдельных статьях:
  - на GWAS метрика по основам засчитывает «исследования геномных ассоциаций», а судья считает это неточным переводом «genome-wide association study»;
  - на статье про волокна судья принимает допустимые варианты, которых нет в списке эталонов.
- Ни одна метрика не видит ошибок вне размеченных терминов. Например, в первой статье «charge conservation» переведено как «экономия заряда».

### Канарейка

Перед полным прогоном пайплайн проверялся на одной статье (2611.17051): 16.7% / 83.3% / 83.3%. Подробный отчёт с примерами по каждой метрике и подсветкой терминов в тексте лежит в [`report/canary_report.html`](report/canary_report.html).

## Как оценить свой переводчик

1. Переведите `text_en` каждой статьи из `data/dataset.json`. Сохраните результат как список `{"article_id", "translation_ru"}`.
2. Метрики 1–2 считаются без внешних сервисов:

   ```python
   import json, importlib.util

   def load(name):
       spec = importlib.util.spec_from_file_location(name, f"nirvana_code/{name}_full.py")
       m = importlib.util.module_from_spec(spec)
       spec.loader.exec_module(m)
       return m

   ds = json.load(open("data/dataset.json"))
   tr = json.load(open("my_translations.json"))
   res = load("baseline_score").main([tr], [ds], None, None)
   print(res["mean_score_exact_pct"], res["mean_score_stem_pct"])
   ```

3. Для метрики 3 соберите промпты через `judge_prep_full.main([tr], [ds], None, None)`. Это поля `system` и `prompt` на каждую статью. Отправьте их в LLM и передайте ответы в `judge_score_full.main([[{"article_id": ..., "answer": ...}]], [ds], None, None)`.

## Ограничения

- Выборка маленькая: 10 статей, 67 терминов. Разница в несколько процентных пунктов между системами может быть шумом.
- Эталоны и варианты размечены одним аннотатором. Списки вариантов неполные, это влияет на метрики 1–2.
- Оценивается только перевод аннотаций, а не полных текстов статей.
- LLM-судья — одна модель с одним прогоном. Его согласие с людьми-экспертами отдельно не измерялось.
